# Архитектура решения

## Контекст

FENEK — приложение для Android, которое превращает запись разговора в структурированную
расшифровку: участники, реплики, временные метки. Запись берётся из памяти телефона или
записывается в самом приложении. Вся обработка (декодирование, определение говорящих,
распознавание речи, правка текста языковой моделью) выполняется на устройстве. Сеть нужна
один раз, чтобы скачать модели.

Результат показывается в приложении и экспортируется в файл. Основной формат экспорта —
JSON из задания, см. [OUTPUT_FORMAT.md](OUTPUT_FORMAT.md).

## Компоненты

```
запись / файл ─► декодер (MediaCodec) ─► 16 кГц моно PCM на диске
              ─► диаризация: сегментация речи + «отпечатки» голосов ─► участники
              ─► реплики (без наложений, ≤ 25 с) ─► распознавание каждой реплики
              ─► [копия на случай сбоя] ─► языковая модель:
                     1) правка текста реплик (с защитой)
                     2) выжимка и задачи
              ─► расшифровка (JSON в личной папке) ─► просмотр, плеер, экспорт
```

| Пакет | Что делает |
|---|---|
| `audio/` | Декодирование любого аудио и видео в PCM 16 кГц, ресемплер, поиск тихих мест |
| `record/` | Запись с микрофона в AAC, отметки, список записей |
| `engine/` | Диаризация (блоки по 10 минут, окна голоса по 2 с, спектральная кластеризация), построение реплик, распознавание, конвейер и этапы прогресса |
| `llm/` | Языковая модель: интерфейс `LlmEngine`, llama.cpp через JNI, правка текста и защита от переписывания, выжимка и задачи, защита от падения |
| `analytics/` | Статистика, темы, «Главное» по правилам (запасной вариант без модели), сроки |
| `model/` | Каталог моделей, загрузка с докачкой и зеркалами, план «скачать всё» |
| `data/` | Расшифровки (JSON), поиск, настройки, копии на случай сбоя |
| `export/` | TXT, Markdown, SRT, VTT, JSON задания, расширенный JSON |
| `service/` | Фоновая обработка, служба записи, плитка, уведомления |
| `ui/` | Экраны на Jetpack Compose |
| `app/src/main/cpp/` | Мост JNI к llama.cpp (`llm_jni.cpp`) и сборка CMake |

### Конвейер обработки

1. **Декодирование.** `MediaCodec` распаковывает файл, каналы сводятся в моно, ресемплер
   (оконный sinc) приводит звук к 16 кГц. Результат пишется на диск, поэтому длинные записи
   не занимают память.
2. **Диаризация.** Запись режется на блоки по 10 минут в тихих местах; модель
   pyannote segmentation 3.0 находит участки речи. «Отпечатки» голосов (3D-Speaker ERes2Net)
   считаются на окнах по 2 с, и все отпечатки записи кластеризуются спектральным методом.
   Число участников можно задать; иначе оно выбирается по качеству кластеризации.
3. **Реплики.** Наложения разрешаются в пользу того, кто уже говорит, мелкие «мигания»
   убираются, паузы короче секунды склеиваются. Реплики длиннее 25 с режутся по тихим местам.
4. **Распознавание.** Каждая реплика распознаётся отдельно, поэтому текст не смешивает
   двух людей. Время реплики берётся из диаризации.
5. **Языковая модель** (режимы переключаются в настройках; по умолчанию включена выжимка, правка текста выключена):
   - *«Исправлять текст»*: реплики пачками по 8 уходят в модель, которая расставляет
     знаки препинания и регистр и исправляет явные ошибки. Ответ принимается, только если
     (без учёта регистра и знаков) изменено не более 30 % слов, число слов осталось в
     пределах 70–140 %, и не пропало ни одно число. Иначе остаётся распознанный текст.
     Спикер и время реплики не меняются никогда; исходный текст сохраняется в `rawText`.
   - *«Выжимка и задачи»*: модель получает пронумерованные реплики и по грамматике GBNF
     возвращает JSON со списками `summary` и `tasks`, где у каждого пункта есть номер реплики.
     Пункты с несуществующим номером отбрасываются. Если модель ничего полезного не вернула,
     работают правила из `analytics/`.
6. **Сохранение.** Расшифровка пишется в `filesDir/transcripts/<id>.json` через временный файл.

## Основные технические решения

- **Распознавание и диаризация: sherpa-onnx 1.13.8 (ONNX Runtime).** Один движок на оба
  этапа, готовые модели, работает на CPU.
- **Языковая модель: llama.cpp `v0.9.0`** (коммит `cd959bae99ff4bed22bef2604f45241c09bbb8c8`),
  собирается из исходников NDK 29.0.14206865 через CMake 3.22.1 под `arm64-v8a` и `x86_64`.
  Формат моделей GGUF, декодирование жадное (одинаковый вход даёт одинаковый ответ).
  Бэкенды ggml грузятся во время работы (`GGML_BACKEND_DL`, `GGML_CPU_ALL_VARIANTS`): в
  `arm64-v8a` семь вариантов под разные наборы инструкций процессора, выбирается лучший
  из поддерживаемых телефоном. 32-битная сборка языковую модель не содержит и работает без неё.
- **Одна модель в памяти.** Распознаватель закрывается до загрузки языковой модели, а она
  выгружается, как только её этапы закончились. Перед загрузкой проверяется свободная память.
- **Бюджет времени языковой модели.** Модель только улучшает расшифровку, поэтому на медленном
  телефоне она не должна растягивать обработку: оба её этапа вместе получают половину длины
  записи, но не меньше 2 и не больше 10 минут (считается с момента, когда модель загружена).
  Запрос получает то, что осталось, а когда осталось меньше 15 с, остальные запросы пропускаются
  и расшифровка завершается с тем, что уже готово (в выжимке тогда работают правила). Если включены
  оба режима, правка берёт не больше половины бюджета. Окна длинного разговора для выжимки
  спрашиваются в порядке «первое, последнее, середины промежутков», чтобы при досрочной остановке
  выжимка покрывала весь разговор, а не только его начало.
- **Защита от падения.** Нативный сбой в модели нельзя перехватить в Kotlin. Поэтому перед
  загрузкой модели создаётся маркер-файл, а перед её запуском расшифровка с распознанным
  текстом пишется в `filesDir/pending/`. Если процесс погиб, при следующем запуске копия
  становится обычной расшифровкой, оба режима модели отключаются, и пользователь получает
  сообщение. При нормальном окончании, ошибке или отмене копия удаляется.
- **Каждая реплика отдельно.** Пачки для правки текста ограничены по числу реплик и по
  символам; длина ответа ограничена (1,5 × вход + 16 токенов) и по времени (60 с на запрос).
- **Один JSON-формат на все данные.** Расшифровки хранятся как JSON с `ignoreUnknownKeys`,
  поэтому файлы прежних версий читаются, а новые поля необязательны.
- **Фоновая работа.** Задание живёт в области приложения, а не экрана; foreground-служба
  держит процесс и показывает прогресс.

## Зависимости и модели

Библиотеки: sherpa-onnx 1.13.8 (Apache-2.0), llama.cpp v0.9.0 (MIT), Jetpack Compose,
kotlinx.coroutines и kotlinx.serialization. Все модели скачиваются один раз и хранятся в
`filesDir/models`.

| Назначение | Модель | Размер | Лицензия |
|---|---|---|---|
| Распознавание (по умолчанию) | GigaAM v3 RNNT, с пунктуацией | 232 МБ | MIT |
| Распознавание | GigaAM v3 CTC | 225 МБ | MIT |
| Распознавание | Zipformer RU (int8), без пунктуации | 73 МБ | Apache-2.0 |
| Распознавание | Whisper Base / Small (int8) | 161 / 375 МБ | MIT |

выбор (см. [TEST_RESULTS.md](TEST_RESULTS.md)).

## Безопасность и приватность

- Записи, тексты и запросы к языковой модели никуда не отправляются. Разрешение `INTERNET`
  используется только для скачивания моделей, которые докачиваются с Hugging Face или зеркал.
- Автобэкап отключён (`allowBackup=false`), расшифровки и аудио лежат в личной папке приложения.
- Службы и провайдер файлов не экспортируются; наружу открыты только главный экран и
  плитка быстрых настроек. Путь записи, пришедший из уведомления, принимается, только
  если это файл в личной папке записей.
- Обмен файлами идёт через `FileProvider` с временным правом чтения.

## Что здесь не проверено

Нативная часть языковой модели собирается (проверено сборкой APK и проверкой экспортируемых
JNI-функций), но на устройстве она ещё не запускалась: у автора не было ни телефона, ни
эмулятора. Скорость и точность с моделью и без неё не измерены.
