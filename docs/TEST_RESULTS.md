# Методика и результаты тестирования

Организаторы сравнивают экспорт приложения с эталонными расшифровками и считают точность
транскрибации (WER) и скорость (RTF). Мы меряем то же самое тем же способом, чтобы цифры
в этом документе можно было проверить.

## Что измеряется

| Показатель | Как считается |
|---|---|
| WER | Расстояние Левенштейна между словами эталона и экспорта, делённое на число слов эталона. Перед сравнением текст приводится к нижнему регистру, «ё» заменяется на «е», знаки препинания удаляются |
| Число говорящих | Число разных `speaker_id` в экспорте, сравнивается с эталоном |
| RTF | Время обработки задания, делённое на длительность записи. Время считается целиком: от начала подготовки до сохранения, вместе с загрузкой моделей и этапами языковой модели. Приложение показывает его в заголовке расшифровки |

## Инструмент оценки

Скрипт `tools/eval/wer.py` использует только стандартную библиотеку Python 3.9+.

```bash
python tools/eval/wer.py --reference tools/eval/sample/reference.json --hypothesis tools/eval/sample/export.json --processing-seconds 3 --duration-seconds 12.2
```

Эталон: JSON той же схемы, что и экспорт, или обычный текстовый файл. Экспорт проверяется по
схеме `{"transcript": [{"speaker_id", "start_ms", "end_ms", "text"}]}`; при нарушении скрипт
называет поле и завершается с кодом 2. Пример вывода на файлах из `tools/eval/sample/`:

```
WER: 0.00% (S=0 D=0 I=0 N=17)
Speakers detected: 2 (reference: 2)
RTF: 0.246
```

Тесты инструмента запускаются из его папки:

```bash
cd tools/eval && python -m unittest
```

## Порядок замера на телефоне

1. Установить APK и один раз открыть приложение с интернетом, скачать модели.
2. Включить режим «в самолёте».
3. Импортировать запись, указать число участников, если оно известно, и запустить расшифровку.
4. Запомнить RTF из заголовка расшифровки (или время из уведомления).
5. Выбрать «Экспорт» → «Сохранить в файл» → «JSON расшифровки (.json)».
6. Забрать файл (`adb pull`) и запустить `tools/eval/wer.py` с эталоном.
7. Повторить с выключенной «Исправлять текст» в настройках и записать обе строки в
   `artifacts/test-results/results.csv`.

## Результаты

**Это результаты эмулятора, не телефона.** Android 15 x86_64, 4 vCPU, 3 ГБ ОЗУ, хост AMD Ryzen 5
5560U; приложение свёрнуто на время обработки, 2 потока. Записи синтезированы (Windows SAPI,
голос Irina; другие участники получены сдвигом тона), реальных записей организаторов в
проверке не было. Таблица целиком: [`artifacts/test-results/results.csv`](../artifacts/test-results/results.csv).

| Запись | Участники (эталон / найдено) | Языковая модель | WER | Время | RTF |
|---|---|---|---|---|---|
| Диалог на 63 с | 2 / 2 | выключена | 2,90 % | 54 с | 0,86 |
| Диалог на 63 с | 2 / 2 | Qwen2.5 0.5B, правка и выжимка | 2,90 % | 91 с | 1,45 |
| Диалог на 63 с | 2 / 2 | Qwen2.5 1.5B, правка и выжимка | 2,90 % | 232 с | 3,69 |
| Планёрка на 65 с | 3 / 3 (число не задавалось) | выключена | 3,75 % | 45 с | 0,69 |
| Звонок на 41 с | 2 / 2 | выключена | 6,98 % | 27 с | 0,66 |

Что из этого следует:

- **Распознавание и диаризация работают** на этих записях: число говорящих найдено верно, в том числе
  без подсказки, WER 3–7 %. Ошибки в основном в числах («пятнадцати часам» → «15:00») и в слове
  «акт» → «а кто». Синтезированная речь чище живой, поэтому на настоящих записях WER будет выше.
- **Правка текста не изменила WER**: GigaAM уже ставит пунктуацию, поэтому нечего исправлять. На
  этих данных она только добавляет время. Выигрыш возможен для моделей без пунктуации
  (Zipformer, Whisper Base), это не измерялось.
- **Выжимка и задачи**: с Qwen2.5 1.5B получились осмысленные пункты и настоящие задачи («Согласовать
  бюджет на следующий квартал», «Обсудить бюджет в следующую среду…»), с Qwen2.5 0.5B нет (она
  копирует первые реплики). Поэтому по умолчанию стоит 1,5B.
- **Стоимость модели**: этапы правки и выжимки добавили 37–178 с к 54 с. В прогоне с 1,5B запрос
  выжимки упёрся в лимит 120 с и показаны выводы на правилах (это штатный откат). В эмуляторе процессор
  делится с гостевой системой, на телефоне цифры будут другими.

Особенности замеров: в первых трёх строках файл получен кнопкой «Сохранить в файл» → «JSON расшифровки»;
строки 4 и 5 посчитаны по сохранённой расшифровке теми же правилами (`speaker_<n>`, миллисекунды).
Строки 1 и 3 получены в релизной сборке (R8), остальные в отладочной.

### Что ещё не измерено

- Реальный arm64-телефон: RTF, нагрев, расход памяти, выбор языковой модели и значения
  «Исправлять текст» по умолчанию.
- Реальные записи (в том числе тестовые записи организаторов) и эталоны с живой разметкой.
- Сравнение с моделями без пунктуации.
